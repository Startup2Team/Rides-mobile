# Package Payment Frontend Contract Matrix

| Operation | Endpoint | Method | Frontend caller | Auth identity | Request DTO | Success DTO | Expected errors | Frontend behavior | Backend authority requirement | Implementation status |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| configuration | `/v1/package-payments/configuration` | `GET` | config query hook | bearer auth | none | `PackagePaymentConfigurationDto` | `unauthorized`, `service_unavailable` | Read mode and provider config; fall back to automatic on local/client failure | backend-owned config | MOBILE READY |
| create claim | `/v1/package-payments/manual-claims` | `POST` | create mutation hook / manual form | authenticated driver | `CreateManualPaymentClaimRequestDto` | `ManualPaymentClaimDto` or safe read model | `invalid_claim`, `duplicate_transaction_reference`, `transaction_reference_required` | Create a draft claim only; never approve locally | driver auth required; client driverId not trusted | MOBILE IMPLEMENTED |
| list own claims | `/v1/package-payments/manual-claims` | `GET` | claims query hook | authenticated driver | `ManualPaymentClaimListQueryRequestDto` | `ManualPaymentClaimCursorListResponseDto` | `forbidden`, `not_found`, `service_unavailable` | Show the driver’s own claims only | ownership enforced by backend | MOBILE READY |
| get own claim | `/v1/package-payments/manual-claims/{claimId}` | `GET` | claim query hook | authenticated driver | path `claimId` | `ManualPaymentClaimReadDto` / detail response | `claim_not_found`, `forbidden` | Render claim status read model | ownership enforced by backend | MOBILE READY |
| submit | `/v1/package-payments/manual-claims/{claimId}/submit` | `POST` | submit mutation hook | authenticated driver | `SubmitManualPaymentClaimRequestDto` | `ManualPaymentClaimDto` | `claim_version_conflict`, `claim_not_found`, `invalid_claim_transition` | Transition to pending review only | driver auth required | MOBILE IMPLEMENTED |
| resubmit | `/v1/package-payments/manual-claims/{claimId}/resubmit` | `POST` | resubmit mutation hook | authenticated driver | `ResubmitManualPaymentClaimRequestDto` | `ManualPaymentClaimDto` | `claim_version_conflict`, `invalid_claim_transition`, `claim_not_reviewable` | Return to pending review after clarification | driver auth required | MOBILE IMPLEMENTED |
| cancel | `/v1/package-payments/manual-claims/{claimId}/cancel` | `POST` | cancel mutation hook | authenticated driver | `CancelManualPaymentClaimRequestDto` | `ManualPaymentClaimDto` | `invalid_claim_transition`, `claim_not_found` | Cancel own claim only | driver auth required | MOBILE IMPLEMENTED |
| admin list | `/v1/admin/package-payments/manual-claims` | `GET` | backend/admin web future | admin/support auth | `AdminManualPaymentReviewQueueRequestDto` | queue response | `forbidden`, `service_unavailable` | Backend review queue only | admin auth required | ADMIN WEB FUTURE |
| admin detail | `/v1/admin/package-payments/manual-claims/{claimId}` | `GET` | backend/admin web future | admin/support auth | path `claimId` | review detail response | `forbidden`, `claim_not_found` | Review claim detail only | admin auth required | ADMIN WEB FUTURE |
| request clarification | `/v1/admin/package-payments/manual-claims/{claimId}/request-clarification` | `POST` | backend/admin web future | admin/support auth | clarification request DTO | review response | `claim_version_conflict`, `claim_not_reviewable` | Request more information; no activation | admin auth required | BACKEND REQUIRED |
| reject | `/v1/admin/package-payments/manual-claims/{claimId}/reject` | `POST` | backend/admin web future | admin/support auth | rejection DTO | review response | `claim_version_conflict`, `claim_not_approvable` | Reject claim safely; no activation | admin auth required | BACKEND REQUIRED |
| approve | `/v1/admin/package-payments/manual-claims/{claimId}/approve` | `POST` | backend/admin web future | admin/support auth | approval DTO | `ManualPaymentApprovalResultDto` | `claim_version_conflict`, `invalid_verification_evidence`, `idempotency_conflict`, `approval_transaction_failed` | Approve only in trusted backend transaction | admin auth required | BACKEND REQUIRED |

Notes:

- driver request fields such as `driverId`, `packageName`, `priceRwf`, `credits`, `bonusCredits`, `durationDays`, and `merchantCode` are compatibility hints only and are never authoritative
- driver claim listing is cursor-based in the frontend contract
- admin contracts are planned for backend and admin web coordination only
